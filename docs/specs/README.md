# Feature specs

One spec per feature, written once the design is agreed and before building starts. A spec is the low-level design plus an ordered task list, written so that one person + AI session can take the feature to complete without rediscovering anything.

## How a feature moves

1. **Propose:** discuss the design in the living design doc (exported to [`DESIGN.md`](../DESIGN.md)).
2. **Agree:** once settled, copy [`_template.md`](_template.md) to `<feature-slug>.md` on a `docs/` branch and fill it in. Link it from its item in [`IMPLEMENTATION_PLAN.md`](../IMPLEMENTATION_PLAN.md).
3. **Build:** implement on a `feature/` branch, ticking off the spec's tasks as you go.
4. **Finish:** the PR that completes the feature marks the spec Done and ticks off the plan item.

A spec that turns out wrong during the build gets updated in the same PR. The spec should always describe what was actually built.
